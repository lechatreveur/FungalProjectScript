**Date**: September 15, 2026
**Experiment**: `2026_08_28_M160`, sequences `5_1_N1_F0` / `F1` / `F2`
**Stages**: 3 (model-based dense tracking), 4 (polarity quantification), 4b (strips)
**SLURM job**: array `2460385`, 21 tasks, partition `compute-short`
**Status**: submitted and running at time of writing
**Purpose**: reproducibility record (P3, P8). Everything needed to re-run this

---

## 1. What is being run and why

Every cell of QC status `good`, `corrected` or `unreviewed`, in **every
fluorescence film it appears in**, is tracked with the model-based dense tracker
and quantified for polarity-site dynamics. The output feeds stages 5 and 6, the
engineered features and the UMAP manifold.

This supersedes the 2026-09-14 run, which covered 700 (film, cell) pairs. That
run selected film positions from the work queue's `sus_pos` column, which lists
only the positions a per-frame QC had flagged **suspect**. It is a defect index,
built for repair runs where processing only flagged intervals is the point.
Used as a cohort definition it inverts the meaning: 554 of the 950 selected
cells have an empty `sus_pos` — because they are clean everywhere — and were
never tracked at all. The resulting feature table sampled "wherever something
looked wrong".

## 3. Exact invocation

Generated by `SingleCellQuantificationHPC/generate_model_based_jobs_m160.py`,
which writes the array, the (currently unusable, see §6) post job, `films.txt`
and a README into the outputs tree, then rsynced to the cluster.

    # workstation
    python SingleCellQuantificationHPC/generate_model_based_jobs_m160.py

    # cluster
    cd /home/hsushen/FungalProjectScript/SingleCellQuantificationHPC/sb_scripts_mbdt_m160
    sbatch model_based_m160_array.sh      # -> job 2460385

One array task per fluorescence film, 21 in total, `--array=0-20%7`, 16 GB and
4 CPUs each, `--time=1-00:00:00` on `compute-short` (3-day cap). A film is the
unit because both stages cache per film: stage 3 reads that film's `_seg.tif`
series, stage 4 computes the film intensity scale once. A per-cell array would
redo that 6,246 times.

Per task, in order:

    python -u run_model_based_dense_tracking.py --exp <movies> \
        --out <outputs>/dense_masks \
        --work-queue <scratch>/work_queue_all_statuses.csv \
        --seed <scratch>/bayesian_tracker_benchmark_307.csv \
        --status good corrected unreviewed --channel FL --films "$FILM"

    python -u quantify_model_based_dense.py --exp <movies> \
        --dense <outputs>/dense_masks --out <outputs>/quant \
        --channel FL --films "$FILM" --workers 4

    python -u build_strips_m160.py --exp <movies> \
        --dense <outputs>/dense_masks --out <outputs>/strips --films "$FILM"

Cells per task range from 251 (`FL1_F2`) to 349 (`FL7_F1`), so the tasks are
well balanced.

## 4. Parameters

Stage 3, `model_based_dense_tracking.py` module constants:

| Parameter | Value | Meaning |
| :--- | ---: | :--- |
| `FUSE_K` | 1.25 | segment longer than this × expected ⇒ fused, cut it |
| `MISS_K` | 0.75 | result shorter than this × expected ⇒ reject the cut |
| `TOL_K` | 0.35 | tip-inside-segment tolerance, as a fraction of r |
| `THETA_WIN` / `THETA_STEP` | 25° / 5° | bend-angle search window and step |
| `SCAN_ANGLE` | False | angle search off during the division scan |
| `PEAK_FRAC_MIN` / `PLATEAU_MAX` | 0.40 / 10 | division-scan confidence gate |
| `BOX_FACTOR` | 2.0 | crop half-size, × the longer keyframe span |
| `WIDTH_PCTL` | 90 | cell width percentile of perpendicular extent |

Stage 4: `quantify_one_object` with `allow_split=True`, `do_plot=False`, one
`ep_refs` dict carried per cell. Film intensity scale from every 10th pixel of
every frame, 99.5th and 1st percentiles (`FindMovieMaxMin`). Keyframes at
t = 0, 50, 100 are quantified from the canonical curated masks so each trace is
exactly 101 frames.

Stage 4b strips: tiles **16 × 56 px**, half the house 32 × 112 in each
dimension. At full size a strip averages 270 KB and 6,246 of them are 1.7 GB on
disk and over 2 GB once base64-embedded in one page. Halving gives 85 KB mean,
0.53 GB total, 32% of the size. `--tile-h 32 --tile-w 112` restores the house
size for a small cohort.

## 6. Deployment, and one dependency removed

The cluster carried only the older pipeline. These were synced:

| Path | Why |
| :--- | :--- |
| `SingleCellQuantificationHPC/{model_based_dense_tracking,run_model_based_dense_tracking,quantify_model_based_dense,build_strips_m160}.py` | the pipeline |
| `Cell_tracking_functions.py` (repo root) | RLE, was absent |
| `scratch/{work_queue_all_statuses,bayesian_tracker_benchmark_307}.csv` | cohort and division seed, were absent |
| `Movies/2026_08_28_M160/sequence_linkage.json` | identity and film order, was absent |

**Dependency removed.** `model_based_dense_tracking.py` imported
`validate_and_decode_rle` / `encode_mask_to_rle` from
`ground_truth_corrector.schemas`. That pulls in `pydantic`, and through the
package's `__init__` it pulls in Flask; neither is installed on the cluster, and
neither belongs in a tracker's import path. It now uses
`Cell_tracking_functions.rle_decode` / `rle_encode`, which P15 already names as
the canonical mask serialisation and which every mask CSV in the pipeline
already uses. Verified byte-identical on all 101 frames of `FL1_F0` cell 37, in
both directions, before deploying.

**Stages 5 and 6 do not run on the cluster** — no scikit-learn, no umap-learn,
and `SingleCellDataAnalysis` is not deployed there. They run on the workstation
after retrieval. `model_based_m160_post.sh` is kept for when that changes and
checks for the packages, exiting early with a message if absent.

## 8. Resume behaviour

Both stages skip completed work, so a timed-out or requeued task resumes.
Stage 4 additionally regenerates any cell whose table is not a complete
101-frame result, or which carries an error row, rather than trusting that a
file exists. That guard exists because a crash mid-run and a routine change
mid-run each left stale output that a plain existence check preserved into a
merged table.

## 9. Known limitations

1. **One cell will be short.** `FL7_F0` cell 421 failed a stage-3 interval on a
   missing keyframe mask and yields 51 frames. It is dropped by the 101-frame
   requirement. That is a stage-1 escalation, not something to patch downstream.
2. **A `bad`-status cell leaked into the previous run's map.** One of the 328
   global cells there maps to a work-queue row marked `bad`. Not yet diagnosed;
   worth re-checking against this cohort.
3. **Model-only frames are included in the fits** on the project owner's
   instruction, with `model_only_pct` recorded per datapoint. In the previous
   cohort they were 3.4% of frames.
4. **Multi-film datapoints are not independent.** A cell in seven films gives
   seven datapoints of the same lineage. That is the reference's own unit, and
   the explorer's link lines exist to make the dependence visible, but it should
   not be read as seven independent observations.
5. **Runtime is estimated, not measured**, at roughly 17 h tracking, 16 h
   quantification and 7 h strips across the whole cohort, from per-cell rates on
   the workstation. Cluster rates will differ.
